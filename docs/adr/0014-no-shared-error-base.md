# 0014: Error 型は基底を共有しない

## ステータス

有効

## 背景

検証の失敗とシステムの異常は、原因ごとに `Error` を継承した Error 型を throw して表す。[Clean Architecture を採用し](./0002-clean-architecture-layers.md)、Use Cases と Interface Adapters のそれぞれが Error 型を throw する。controller はそれらを catch し、Error 型ごとに終了コードを対応づけ、対応づけていない例外を不明として扱う。Error 型に共通の基底を定義するかを決める必要がある。

## 選択肢

### 選択肢 A: 基底を定義しない

各 Error 型は `Error` を直接継承する。

利点は、各 Error 型が他の Error 型と型を共有せず、1 つを変えても他に影響しないことである。

欠点は、Error 型をレイヤー単位でまとめて扱う手段がないことである。

### 選択肢 B: レイヤー共通の基底 Error 型を定義する

レイヤーごとに基底の Error 型を定義し、そのレイヤーの Error 型はすべて基底を継承する。

利点は、`instanceof` 1 回で例外がどのレイヤーのものかを判別できることである。

欠点は、基底を変えると、そのレイヤーのすべての Error 型に影響することである。

## 決定

選択肢 A を採用する。

controller が Error 型ごとに対応づけるため、レイヤー単位でまとめて扱う場面がなく、基底を共有する利点が生じない。

### 選定に影響しなかった点

特になし。

## トレードオフ

Error 型をレイヤー単位でまとめて扱う手段を持たない。
