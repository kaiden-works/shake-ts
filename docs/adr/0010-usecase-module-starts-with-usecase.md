# 0010: usecase のモジュールは usecase の関数を先頭に書く

## ステータス

有効

## 背景

[Use Cases は feature ごとに置く](./0003-shared-entities-and-per-feature-usecases.md)と決めた。usecase のモジュールは、usecase の関数に加えて、usecase が引数で受け取る port と依存の型、throw する Error 型を 1 ファイルに持つ。型と Error 型を先に書くと本体の関数がファイルの末尾になり、読み手はファイルを開いてから本体を探す必要がある。本体の位置を読み手に示す方法を決める必要がある。

## 選択肢

### 選択肢 A: 区切りのコメントで示す

型、Error 型、本体のまとまりごとに、何のまとまりかを書いたコメントを置く。

利点は、宣言の順番を変えずに済むことである。

欠点は、コードから読み取れる what を繰り返すコメントになることである。

### 選択肢 B: 本体を先頭に書く

usecase の関数をファイルの先頭に書き、本体を読んで現れる順に、依存の型と port、Error 型を続ける。

利点は次のとおり。

- 読み手がファイルを開いた位置に本体がある
- `function` 宣言は hoisting され、型は位置によらず参照できるため、本体が後ろの定義を使える

欠点は、Error 型に `class` を使うため、モジュールの評価時に Error 型を参照する式を本体より前に書けないことである。

## 決定

選択肢 B を採用する。

選択肢 A は what を書くコメントになり、コメントに why を書く方針と合わないためである。

### 選定に影響しなかった点

特になし。

## トレードオフ

モジュールの評価時に Error 型を参照する式は、Error 型の後ろに書く必要がある。
