# 0011: port は失敗を値で返す

## ステータス

有効

## 背景

[Clean Architecture を採用し](./0002-clean-architecture-layers.md)、usecase は port を通して外部とやりとりする。port 実装は Node.js の API と外部ライブラリーを呼び、それらは失敗を例外で伝える。usecase は仕様の検証手順として失敗を扱うため、port の失敗を Use Cases の Error 型にする必要がある。port 実装から usecase へ失敗をどう渡すかを決める必要がある。

## 選択肢

### 選択肢 A: 値で返す

port は成功と失敗を判別できる値を返す。port 実装は、Node.js の API と外部ライブラリーの例外のうち扱うと決めたものだけを catch して失敗の値にする。失敗の値は原因を文字列で持つ。それ以外の例外は catch せず throw したままにし、検証の失敗と区別する。usecase は失敗の値を受けて Error 型を throw する。

利点は次のとおり。

- port の型が失敗の種類を列挙し、usecase はそれだけを扱えばよい
- 扱うと決めた例外が port 実装で止まり、usecase に届かない

欠点は、扱うと決めた例外の cause とスタックトレースを usecase に渡さず、原因の文字列だけにすることである。

### 選択肢 B: 例外を throw する

port 実装は失敗を例外で throw する。usecase は catch して Error 型に包み直す。

利点は、例外の cause とスタックトレースを失わずに usecase へ渡せることである。

欠点は、usecase が catch の中で、想定した失敗と port 実装の不具合による例外を見分ける必要があることである。

## 決定

選択肢 A を採用する。

port 実装は想定した失敗をすべて値にできるため、例外でしか表せない失敗はない。失敗の原因は検証の失敗の報告に使う粒度で足り、cause とスタックトレースを usecase へ渡す必要がないため、選択肢 B の利点が生じない。

### 選定に影響しなかった点

特になし。

## トレードオフ

失敗の原因は文字列になり、検証の失敗の報告に使える粒度に留まる。
