# 0001: Node.js で TypeScript を直接実行する

## ステータス

有効

## 背景

参照実装は[パッケージとして配布しない](../PRD.md#制約前提)。利用者はリポジトリーを checkout して実行する。JavaScript に変換して出力する必要がなく、TypeScript をどう実行するかを決める必要がある。

## 選択肢

### 選択肢 A: Node.js の型消去で直接実行する

Node.js 24 は `.ts` ファイルの型注釈を消去して実行する。

利点は次のとおり。

- 実行のための依存がない
- 原本のファイルがそのまま動き、スタックトレースの行番号がずれない

欠点は次のとおり。

- enum、namespace、constructor の parameter properties、decorator を使えない
- import に `.ts` 拡張子が必要となる

### 選択肢 B: tsc でトランスパイルした JavaScript を実行する

tsc で JavaScript を出力し、それを実行する。

利点は、TypeScript のすべての構文を使えることである。

欠点は次のとおり。

- 実行の前にビルドが挟まる
- 読者が原本と出力を対応させる手間がある

### 選択肢 C: tsx で実行する

tsx が esbuild で変換しながら実行する。

利点は、TypeScript のすべての構文を使え、vitest と同じ esbuild で変換することである。

欠点は次のとおり。

- 実行のための依存が増える
- tsc の検査と esbuild の変換が二重になる

## 決定

選択肢 A を採用する。

参照実装は読まれるためにある。原本のファイルがそのまま動けば、読者は原本と出力を対応させずに済む。実行のための依存も、tsc の検査と変換の二重化も持たない。使えない構文はいずれも使わない方針の構文で、制約にならない。

### 選定に影響しなかった点

特になし。

## トレードオフ

import に `.ts` 拡張子が必要となる。
