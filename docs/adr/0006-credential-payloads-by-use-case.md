# 0006: 例の VC ペイロードをユースケースごとに置く

## ステータス

有効

## 背景

[URL で公開する文書は URL のホスト名とパスのとおりに置く](./0005-examples-layout-by-host-and-path.md)と決めた。例には VC ペイロードもあり、その置き方を決める必要がある。

到達 VC と到達への保証 VC は URL を持たず、保持者が持つ。定義への保証 VC は URL で公開するが、公開するのは署名済みの SD-JWT であり、VC ペイロードとはバイト列が異なる。どの VC ペイロードも、URL で公開する文書と同じ規則では置けない。

## 選択肢

### 選択肢 A: `iss` の発行主体のディレクトリーに置く

VC ペイロードを `examples/published/<iss のホスト名>/` 配下に置く。

利点は、発行主体ごとに文書と VC ペイロードがまとまることである。

欠点は、`examples/published/` に URL を持たないファイルが混ざり、配信のときに除く必要があることである。

### 選択肢 B: ユースケースごとのディレクトリーに置く

VC ペイロードを `examples/credentials/<ユースケース>/` に置く。

利点は次のとおり。

- `examples/published/` が URL で公開する文書だけになり、そのまま配信できる
- ユースケースの到達と保証の関係を 1 つのディレクトリーで読める

欠点は、VC ペイロードと `iss` の Issuer 文書が別のディレクトリーに分かれることである。

## 決定

選択肢 B を採用する。

`examples/published/` を URL で公開する文書だけにすると、取得と配信の規則に例外がなくなる。

### 選定に影響しなかった点

特になし。

## トレードオフ

VC ペイロードから `iss` の Issuer 文書をたどるには、URL を `examples/published/` のパスに読み替える必要がある。
