# 0015: 依存は公開から 3 日以上たった版を使う

## ステータス

有効

## 背景

本リポジトリーは npm パッケージ、GitHub Actions の Action、mise が管理する Node.js と pnpm に依存する。[2025 年 9 月に npm の chalk と debug のメンテナーのアカウントが乗っ取られ](https://www.aikido.dev/blog/npm-debug-and-chalk-packages-compromised)、悪意のあるコードを含む版が公開された。メンテナーは約 2 時間後に取り下げを始めた。公開直後の版を取り込まなければ、この種の混入を避けられる。依存は毎日更新する。依存の版を公開から何日待って使うかを決める必要がある。

## 選択肢

### 選択肢 A: 公開直後の版を使う

待たずに最新の版を使う。

利点は、脆弱性の修正版をすぐ取り込めることである。

欠点は、混入した版を取り込んでしまうことである。

### 選択肢 B: 公開から 3 日以上たった版を使う

公開から 3 日以上たった版のうち最新のものを使う。npm パッケージは [pnpm の `minimumReleaseAge`](https://pnpm.io/settings/dependency-resolution#minimumreleaseage) で、Node.js と pnpm は [mise の `minimum_release_age`](https://mise.jdx.dev/configuration/settings.html#minimum_release_age) で 3 日を強制する。Action は公開日を確かめて選ぶ。

利点は次のとおり。

- 数時間から数日で見つかる混入を避けられる
- 脆弱性の修正版の取り込みの遅れが 3 日に収まる

欠点は、3 日より長く残った混入を避けられないことである。

### 選択肢 C: 公開から 7 日以上たった版を使う

公開から 7 日以上たった版のうち最新のものを使う。強制の手段は選択肢 B と同じである。

利点は、選択肢 B より長く残った混入も避けられることである。

欠点は次のとおり。

- 脆弱性の修正版の取り込みが 7 日遅れる
- 毎日更新する運用では、待っている版が常に残る

## 決定

選択肢 B を採用する。

事件では取り下げまで約 2 時間であり、3 日で余裕がある。毎日更新する運用で、待ちが短い。

### 選定に影響しなかった点

特になし。

## トレードオフ

3 日より長く残った混入は避けられない。
