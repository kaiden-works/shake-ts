# 0013: テストは in-source testing で書く

## ステータス

有効

## 背景

単体テストをどこに置くかを決める必要がある。テストランナーの vitest は、実装と同じファイルにテストを書く [in-source testing](https://vitest.dev/guide/in-source.html) と、別ファイルの両方に対応する。

## 選択肢

### 選択肢 A: in-source testing で書く

各モジュールの末尾に `if (import.meta.vitest)` のブロックを置き、その中にテストを書く。

利点は次のとおり。

- 公開しない関数を、公開せずにテストできる
- テストと実装が同じファイルにあり、実装を変えたときにテストが目に入る

欠点は、実行時にテストコードを読み飛ばす分岐が各モジュールに入ることである。

### 選択肢 B: 別ファイルに書く

`*.test.ts` を実装のファイルと並べて置く。

利点は、実装のファイルにテストが混ざらないことである。

欠点は次のとおり。

- テストのためだけに関数を公開する必要がある
- テストの置き場所と命名の規則を決め、守る必要がある

## 決定

選択肢 A を採用する。

公開する関数をテストの都合で決めないためである。各モジュールに分岐が入る欠点は、置き場所と命名の規則を決めて守る手間より軽い。

### 選定に影響しなかった点

#### mock の粒度

mock の粒度はテスト戦略で定め、テストの置き場所の選択に影響しない。

## トレードオフ

各モジュールに `import.meta.vitest` の分岐が入る。
