# shake-ts PRD

shake-ts は、kaiden shake 到達クレデンシャル仕様の参照実装である。以降、この仕様を仕様と略す。

## ターゲットユーザー

| セグメント     | 前提条件                                                                                                    |
| -------------- | ----------------------------------------------------------------------------------------------------------- |
| 検証者         | 仕様の検証手順を自分の言語と環境で実装する。自分の実装の結果を参照実装と突き合わせたい                      |
| 評価者と保証者 | Issuer 文書、Goal、Rubric、EndorsementList と VC ペイロードを作り、発行する。発行前に自分の文書を検査したい |
| 仕様の策定者   | 仕様の改訂が例と検証手順に与える影響を、実装で通して確かめたい                                              |

## 背景 / 課題

仕様は検証手順を文章で定める。文章だけでは、手順の解釈が実装者ごとに割れていても気づけない。手順を最初から最後まで実行できる実装ですべての例を検証し、仕様の不備を見つける必要がある。

検証者は、仕様が定める取得、キャッシュ、署名検証、文書の検査を文章だけから実装すると、解釈が合っているかを確かめられない。動く参照実装があれば、同じ入力に対する結果を突き合わせられる。

評価者と保証者は、公開する文書と VC ペイロードが仕様に適合するかを発行前に確かめる手段を持たない。発行後に検証者側で失敗すると、保持者が不利益を受ける。

## 制約・前提

- 規範は仕様の文書であり、実装との食い違いは仕様を正とする
- 言語は TypeScript とし、Node.js 24 以降で動く
- パッケージとして配布しない
    - 利用者はリポジトリーを checkout して実行する
- テストはネットワークに接続せずに実行できる
- 仕様の例は本リポジトリーの `examples/` に置く

## スコープ

### 検証 CLI

仕様の検証手順を最初から最後まで実行する。到達 VC、到達への保証 VC、定義への保証 VC の各手順と、共通の検証、文書の取得と保持、文書の検査、キャッシュの規則を含む。

検証の成否と、失敗した場合はどの手順で失敗したかを出力する。

### 発行前チェック CLI

Issuer 文書、Goal、Rubric、EndorsementList と VC ペイロードを入力に取り、仕様に適合するかを検査する。スキーマ、参照、完全性ハッシュ、Goal の issuer と iss の一致を含む。検証手順のうち、文書だけで確かめられる項目を検査する。

参照先の現在の内容から完全性ハッシュを計算し直し、文書に書き込む。

### 発行 CLI

VC ペイロードに署名し、SD-JWT を作る。有効期限は実行時刻から計算する。

### 提示 CLI

発行 CLI が作った SD-JWT に Key Binding JWT を付け、提示を作る。入力は SD-JWT、保持者鍵、Authorization Request の client_id と nonce である。Key Binding JWT は [RFC 9901](https://www.rfc-editor.org/rfc/rfc9901.html#section-4.3) に従い、`sd_hash`、`aud`、`nonce`、`iat` を持つ。署名アルゴリズムは Ed25519 と ES256 とする。

### 例

仕様のユースケースごとに、Issuer 文書、Goal、Rubric、EndorsementList、VC ペイロード、署名済み VC を置く。完全性ハッシュは発行前チェック CLI で、署名は発行 CLI で生成する。

## 非スコープ

- ウォレット
    - 提示 CLI は保持者鍵と Authorization Request の値を引数で受け取るだけで、ウォレットを実装しない
- 発行サーバーと検証サーバー
- OpenID4VCI と OpenID4VP のフロー
    - 検証 CLI は Authorization Request の値を入力として受け取るだけで、フローを実装しない
- UI
- npm と他言語へのパッケージとしての配布

## リリース基準

- 検証 CLI が、仕様に適合する文書と VC を pass とし、改竄した入力を改竄の種類ごとに fail とする
- 発行前チェック CLI の検査結果が検証 CLI の文書の検査と一致する
- 発行 CLI の出力に提示 CLI で Key Binding JWT を付けたものを検証 CLI が pass とする
- 発行前チェック CLI がすべての例を pass とする
